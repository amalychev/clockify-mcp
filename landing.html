What this is, in plain words

Clockify is where your hours live. An AI assistant on its own cannot reach it — no login, no idea what your projects are called. This service is the bridge, and it is already running, so there is nothing to install.

01

You point your assistant at one URL

A single command adds clockify-mcp.webapace.ink/mcp as a tool provider. No download, no build, no Node.js.

02

You paste your Clockify API key

It travels as one header with each request. The service holds no accounts and stores nothing between calls.

03

Your timesheet becomes conversation

"Log two hours on the migration, starting at 14:00" — and it is in Clockify, on the right day, in the right zone.

What you need before you start

  • A Clockify account — the free plan is enough for everything except reports, expenses, invoices and approvals.
  • Your personal API key. Getting it takes thirty seconds and is step 1 below.
  • An assistant that speaks MCP — Claude Code, Claude Desktop, Cursor and others.

Setup

Two steps, about two minutes

Copy your Clockify API key

This is the key the server uses to act in Clockify on your behalf.

  1. Open app.clockify.me and sign in.
  2. Click your avatar in the top-right corner → Profile settings.
  3. Scroll to the very bottom, to the API section.
  4. Click Generate if there is no key yet, then copy the value. It is a long string of letters and digits.
The key is you. It carries every permission your account has in every workspace you belong to. Treat it like a password: never commit it to a repository, and regenerate it in that same screen if it leaks — the old one stops working immediately.

Connect your assistant

Pick the tool you use. One value is yours to fill in: the key from the previous step.

One command in the terminal:

claude mcp add --transport http clockify \
  https://clockify-mcp.webapace.ink/mcp \
  --header "X-Clockify-Key: YOUR_API_KEY"

That is the whole setup; the tools appear immediately. Working on one project? Add a second --header "X-Clockify-Project-Id: …" and every hour logged through this connection books itself there. To keep the key out of the config file, write --header "X-Clockify-Key: ${CLOCKIFY_API_KEY}" instead and export the variable in your shell.

Prefer to write the configuration by hand? Create a file named .mcp.json in the root of the repository you work in — everyone who opens that repository gets the same setup. Copy this and fill in the blanks: 

{
  "mcpServers": {
    "clockify": {
      "type": "http",
      "url": "https://clockify-mcp.webapace.ink/mcp",
      "headers": {
        "X-Clockify-Key": "",
        "X-Clockify-Workspace-Id": "",
        "X-Clockify-Project-Id": ""
      }
    }
  }
}

Three values, and only the first is required:

  • X-Clockify-Key — the key from step 1. Without it every call is refused with No Clockify API key supplied.
  • X-Clockify-Workspace-Id — optional. Leave it empty and the workspace you are currently active in is used, which is right for most people. Fill it in if you belong to several and keep ending up in the wrong one; clockify_list_workspaces prints the ids.
  • X-Clockify-Project-Id — optional, and the reason to put this file in a repository: everything logged through this connection lands on that project without anyone naming it. A request that names its own project still wins. A project name works here too, if you prefer reading it.

The same object works anywhere your client keeps MCP servers — the tabs on either side of this one are just different file names. Add "X-Clockify-Workspace-Lock": "true" to confine the assistant to that one workspace, or "X-Clockify-Read-Only": "true" to forbid every change; both are explained under Safety.

Do not commit a real key. Keep .mcp.json out of version control, or write "X-Clockify-Key": "${CLOCKIFY_API_KEY}" — Claude Code and Cursor substitute environment variables, so the file stays shareable and the secret stays in your shell.

Open Settings → Developer → Edit config, which opens claude_desktop_config.json, and add: 

{
  "mcpServers": {
    "clockify": {
      "type": "http",
      "url": "https://clockify-mcp.webapace.ink/mcp",

      }
    }
  }
}

Save the file and restart the app completely (quit, not just close the window).

Optional headers

Everything below has a sensible default; add them only if you want the behaviour.

HeaderWhat it does
X-Clockify-Keyrequired Your personal API key
X-Clockify-Workspace-IdDefault workspace. Without it, the one your account is active in
X-Clockify-Workspace-Locktrue confines every tool to that workspace and refuses anything wider
X-Clockify-Project-IdThe project new entries are logged to when the request names none. An id or a project name
X-Clockify-Read-Onlytrue refuses every tool that would change something
X-Clockify-TimezoneIANA zone such as Europe/Zurich, overriding the one on your Clockify profile
Authorization: Bearer …Accepted instead of X-Clockify-Key by clients that only send bearer tokens

Where to find the workspace and project ids

Both are 24-character strings, and Clockify puts both in the address bar — you never have to call the API to read them off.

  1. Workspace id. Click Settings in the left sidebar. The address becomes app.clockify.me/workspaces/5e8395d5261ba37dee85a378/settings — the part in the middle is the id.
  2. Project id. Open Projects and click the project you want. The address becomes app.clockify.me/projects/60f9c8b1a2d4e51f3c7b8a29/… — again, the chunk after /projects/.

Or connect with the key alone and ask: which workspaces am I in? and find the project called Frontend answer with the ids, ready to paste. Then restart the client — MCP configuration is read at startup, so an edited file changes nothing until you do.

A name works instead of an id. "X-Clockify-Project-Id": "Website redesign" is resolved against your workspace on first use. It is easier to read, but a rename in Clockify breaks it, and a name matching several projects is refused rather than guessed — so for a configuration that should keep working, paste the id.

Verify

Check that it works

Ask your assistant one question. If it answers, everything is wired up.

Who am I in Clockify?clockify_whoami

You should get your name, your email, the workspace you are active in and your time zone. That last one matters: every "09:00" you say later is read in that zone.

To check the service itself rather than your configuration:

curl https://clockify-mcp.webapace.ink/health

It answers {"status":"ok"} when the endpoint is up.

The part that usually goes wrong

Your words, your clock

Clockify stores everything in UTC. People describe work in local time. Getting that conversion wrong is how entries end up on the wrong day — so this server does it properly, once, in the one place it belongs.

It uses your zone, not the server's

The zone comes from your Clockify profile. "09:00" means nine in the morning where you are, no matter where this service runs.

Daylight saving is handled

The offset is resolved for that specific date, so an entry on the night the clocks change lands at the wall-clock time you asked for.

Say it however you like

09:00, 2026-08-05 09:00, yesterday, now, or a full ISO instant when you want to be exact.

Durations, the way people say them

You writeIt means
2h30mTwo hours thirty minutes
1.5hNinety minutes
90mNinety minutes
90Ninety minutes — a bare number is read as minutes
PT2H30MTwo hours thirty, in the ISO form Clockify itself returns

Names instead of ids

Every tool that takes a project, a task or a tag also takes its name. "Log an hour on the website redesign" resolves Website redesign to its id for you. If the name matches more than one thing, you get the candidates back rather than a silent guess at the wrong project.

Totals without a paid plan. Clockify's Reports API needs a paid subscription. clockify_time_summary adds up the time entries themselves instead, so totals per project, per day or per tag work on the free plan too.

Safety

Keeping the assistant on a short leash

Two headers cover the two things people worry about: it changing something it should not, and it seeing a workspace it should not.

Read-only

X-Clockify-Read-Only: true refuses every tool that writes. Reporting, reviewing and answering "how much did we spend on this client" all still work.

One workspace only

X-Clockify-Workspace-Id plus X-Clockify-Workspace-Lock: true confines every tool to that workspace. Listing the others is refused, and so is a raw API call that points anywhere else. Add X-Clockify-Project-Id and everything logged through that connection lands on one project as well.

Deletion needs saying so

Deleting an entry, a project, a client or a tag requires an explicit confirmation flag, so it cannot happen as a side effect of a vaguely worded request.

What the service keeps

Nothing. No accounts, no database, nothing written to disk. Your key and the data it fetches pass through in one request and are gone when it ends; the server talks to exactly two parties, your assistant and Clockify. Whatever the assistant reads does, of course, become part of your conversation with it — the same as pasting it yourself. If your policy forbids credentials leaving your network, run your own copy; it is the same code.

FAQ

Questions people actually ask

Do I need a paid Clockify plan?

No. Timers, time entries, projects, tasks, tags, people and time off all work on the free plan, and clockify_time_summary totals your time by adding up the entries themselves. Only the Reports API, expenses, invoices, approvals and custom fields are paid features; those tools return a 403 that says so.

Which time zone are my hours logged in?

The one set on your Clockify profile, which clockify_whoami reports. Say "09:00" and it means nine in the morning where you are. Send X-Clockify-Timezone with an IANA name such as Europe/Zurich to override it, or give a full ISO instant to bypass the question entirely.

Can it overwrite or delete my existing time entries?

Only if you ask. Deleting requires an explicit confirm flag, and sending X-Clockify-Read-Only: true refuses every tool that changes anything, which makes the connection safe for reporting and review.

Where does my API key go?

It travels as a header with each request and is used to call Clockify. The service keeps no accounts, no database and writes nothing to disk. If your policy forbids credentials passing through someone else's host, run the container yourself — it is the same code.

Can I keep the assistant inside one workspace?

Yes. Set X-Clockify-Workspace-Id to the workspace and X-Clockify-Workspace-Lock to true. Every tool is then confined to it, listing other workspaces is refused, and even the raw API escape hatch has to address that workspace.

Do I have to look up project ids?

No. Every tool that takes a project, task or tag also accepts its name. An ambiguous name is reported with the candidates instead of being guessed at.

Can everything be logged to one project automatically?

Yes — that is what X-Clockify-Project-Id is for. Set it to a project id (or a project name) and every entry written through that connection lands there unless the request names a project of its own. Put it in a repository's .mcp.json and the hours from that repository book themselves correctly.

It is a default, not a lock: listing and summarising still cover the whole workspace, and editing an existing entry never moves it. To find the id, open the project in Clockify — the address becomes app.clockify.me/projects/60f9c8b1a2d4e51f3c7b8a29/….

Can it log time for other people?

With an admin key, yes: pass user_id and the entry is written through the admin endpoint. With an ordinary member key Clockify refuses, which is the correct outcome.

What happens if I ask for a day that is already approved?

Clockify locks approved and archived periods, and the API refuses to write into them. The tool passes that refusal straight through rather than pretending the entry was created.

Can I connect two Clockify accounts at once?

Yes. Add two entries with different names and different keys — for example clockify and clockify-agency. The assistant sees both sets of tools and picks by name.

Something has no tool. Am I stuck?

No. clockify_api_request reaches any endpoint of the Clockify API, including the reports and time-off hosts, while still respecting read-only mode and the workspace lock.

Self-hosting

Running it yourself

One case needs your own copy: a policy that forbids credentials passing through someone else's host. The code is public and runs in a container or as a local process.

As a container

The image serves the same landing page on / and the same MCP endpoint on /mcp. Point your assistant at your own address instead of this one; every header on this page behaves identically.

As a local process

Over stdio, with the API key in an environment variable and nothing listening on a port at all. Nothing leaves your machine except the calls to Clockify itself.

Everything is documented in the repository. The README covers both modes, every environment variable, the Docker build, the deployment settings, and how to add tools of your own.
